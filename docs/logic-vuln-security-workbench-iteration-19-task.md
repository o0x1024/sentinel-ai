## 1. 本轮目标

上一轮已经支持：

- 时间线活动节点直接复制目标定位链接

但它复制的仍然是“证据 / 草案 / 执行结果”的定位，不是“时间线节点本身”的定位。

这会带来两个限制：

1. 普通备注节点还不能独立分享
2. 想定位到复盘链上的某一个具体节点时，还缺少自己的锚点

因此本轮目标是：

`为时间线节点本身建立独立锚点和深链接。`

---

## 2. 本轮实现

### 2.1 时间线节点锚点

时间线中的每个节点现在都具备：

- 独立 DOM 锚点 ID
- 独立时间线项 ID

不再依赖目标证据或目标草案来间接定位。

### 2.2 `timelineId` 深链接

工作台案件详情新增：

- `timelineId`

query，用来直接定位到复盘页中的某一条节点。

### 2.3 备注节点也可精确定位

因为 `timelineId` 不区分系统活动和人工备注，所以现在：

- 系统活动
- 人工备注

都可以生成自己的精确定位链接。

### 2.4 复盘页滚动与高亮

复盘页在收到 `timelineId` 后，会：

- 自动滚动到对应节点
- 对对应节点高亮

这样分享出去的链接会真正落到时间线里的目标项，而不是只切到复盘 tab。

### 2.5 节点级复制入口

时间线现在的：

- `复制节点链接`

会复制基于 `workbenchTab=review + timelineId=...` 的精确链接。

---

## 3. 当前收益

这一轮完成后，时间线从“可操作的调查入口”进一步升级成了“可复盘的精确锚点”：

1. 备注节点可以单独分享
2. 系统活动和人工备注有了统一定位模型
3. 调查协作时可以直接落到复盘链中的具体一条记录

---

## 4. 当前限制

这一轮仍然保持轻量：

1. `timelineId` 目前只在复盘页内部生效
2. 还没有把时间线筛选状态同步到 URL
3. 还没有支持浏览器 hash 形式的锚点

---

## 5. 下一轮建议

如果继续推进，下一轮最值得做的是：

1. 把时间线筛选和搜索也同步到 URL
2. 支持复制“节点链接”与“节点目标链接”两种不同语义
3. 在案件时间线里增加节点级快捷摘要复制
