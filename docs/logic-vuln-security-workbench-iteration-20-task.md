## 1. 本轮目标

在上一轮之后，工作台主链路已基本闭合，但还有两处明显缺口：

1. 复盘页虽然支持搜索和筛选，但这部分状态还没有进 URL
2. 执行草案里非只读计划仍然只能停留在“需人工确认”的提示上，没有真正的确认执行入口

因此本轮目标是：

`把复盘视图做成可恢复状态，并把非只读执行从“阻断”推进到“人工确认后可执行”。`

---

## 2. 本轮实现

### 2.1 时间线搜索和筛选同步到 URL

工作台案件详情现在新增两类 query：

- `timelineSearch`
- `timelineFilter`

当用户在复盘页修改搜索词或筛选条件时，这两项会同步写回 URL。

### 2.2 复盘页状态恢复

当通过链接重新进入案件详情时，复盘页会从 URL 恢复：

- 时间线搜索词
- 时间线筛选项
- `timelineId` 定位节点

这样“复盘视图”本身已经具备可分享和可恢复能力，而不是只有节点定位。

### 2.3 非只读执行的人工确认入口

执行草案面板现在对非只读草案提供：

- `人工确认执行`

按钮，而不再是完全禁用。

### 2.4 执行前确认

真正执行非只读草案前，前端会弹确认框，明确说明：

- 当前草案不是只读
- 仅会执行极小批次的变异请求
- 需要确认当前环境允许进行此类测试

### 2.5 后端保守放行

后端执行命令新增显式确认参数。

只有在：

- 草案非只读
- 前端明确传入确认标记

时，后端才允许放行执行。

同时为了控制风险，当前非只读执行仍然保持保守：

- 仅执行极小批次候选值
- 不走大规模自动化

---

## 3. 当前收益

这一轮完成后，工作台当前阶段里“剩余最明显的待实施项”已经基本收口：

1. 复盘页自身已经可恢复、可分享
2. 执行草案不再只有只读路径
3. 非只读验证进入了“人工确认 + 小范围执行”的受控阶段

---

## 4. 当前限制

这一轮仍然保持保守：

1. 非只读执行仍然是小批次，不做大规模自动化
2. 时间线搜索和筛选虽然已入 URL，但还没有做更复杂的组合恢复
3. 复盘页状态还没有和浏览器历史行为做更细粒度联动
