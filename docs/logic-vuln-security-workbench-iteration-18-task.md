## 1. 本轮目标

上一轮已经支持：

- 复制当前案件定位链接
- 深链接到 tab / 证据 / 草案 / 执行结果

但如果用户正处于案件时间线，仍然需要：

1. 先点击跳到目标
2. 再去页头复制

链路还是偏长。

因此本轮目标是：

`让时间线活动节点本身就能直接复制定位链接。`

---

## 2. 本轮实现

### 2.1 时间线节点复制入口

对于具备跳转目标的系统活动节点，现在除了：

- 查看证据
- 查看草案
- 查看执行结果
- 查看案件概览

之外，还会直接显示：

- `复制定位链接`

### 2.2 复制逻辑收口

复制逻辑没有下沉到时间线组件内部，而是继续保持在工作台 page 层统一生成。

这样可以保证：

- 链接结构只有一套
- 继续复用已有的列表态 query
- 后续如果 URL 结构调整，不需要改多个组件

### 2.3 复制内容

时间线节点复制出来的链接会同时保留：

- 当前列表态
- 目标 tab
- 目标证据 / 草案 / 执行结果

因此它不是纯案件链接，而是可以直接落到对应节点的精确链接。

---

## 3. 当前收益

这一轮完成后，案件时间线从“导航入口”进一步变成了“分享入口”：

1. 在复盘链上就能直接复制目标定位
2. 不必先跳转再复制
3. 调查协作时分享成本更低

---

## 4. 当前限制

这一轮仍然保持轻量：

1. 只对具备目标定位的系统活动开放复制
2. 普通备注节点还没有独立定位链接
3. 还没有支持批量复制多个节点链接

---

## 5. 下一轮建议

如果继续推进，下一轮最值得做的是：

1. 为时间线节点补独立锚点 ID
2. 让备注节点也能生成自身定位链接
3. 支持“复制当前列表链接”和“复制节点定位链接”的双入口区分
