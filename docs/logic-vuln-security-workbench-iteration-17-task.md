## 1. 本轮目标

上一轮已经支持：

- 案件详情深链接
- 目标定位
- 自动滚动
- 复制当前定位链接

但工作台列表本身的上下文仍然不可恢复：

- 搜索条件
- 状态筛选
- 分页
- 每页数量

切到案件后虽然可以返回列表，但列表态本身还没有真正进入 URL。

因此本轮目标是：

`把案件列表的筛选和分页也同步到 URL，并在案件详情中继续保留。`

---

## 2. 本轮实现

### 2.1 列表态 URL 参数

工作台列表现在会把以下状态同步到 URL：

- `search`
- `status`
- `page`
- `pageSize`

其中默认值会被省略，避免 URL 过长。

### 2.2 从 URL 恢复列表状态

页面进入时会从 URL 读取列表态并恢复到本地 UI：

- 搜索框
- 状态筛选
- 页码
- 每页数量

并据此刷新案件列表。

### 2.3 案件详情保留列表态

从列表进入案件详情后，案件路由会继续保留列表 query。

这意味着：

- 从案件返回列表时不会丢失原有筛选
- 复制案件定位链接时也能带上当前列表上下文

### 2.4 统一同步入口

本轮把列表相关的：

- 搜索回车
- 刷新
- 切页
- 改筛选
- 重置

统一收口到同一套 URL 同步入口，避免列表状态和路由状态再次分裂。

---

## 3. 当前收益

这一轮完成后，安全工作台的导航链更完整了：

1. 列表态可以分享和恢复
2. 列表进入案件再返回时不会丢上下文
3. 案件链接也能同时携带列表和案件内定位信息

---

## 4. 当前限制

这一轮仍然保持轻量：

1. 还没有把案件列表排序写入 URL
2. 还没有支持多个筛选条件组合持久化
3. 还没有把安全中心上层 tab 状态一起纳入统一链接模型

---

## 5. 下一轮建议

如果继续推进，下一轮最值得做的是：

1. 给时间线节点增加单独的复制定位链接入口
2. 把案件列表排序和视图模式同步到 URL
3. 从漏洞中心进入工作台时支持直接带入列表和定位参数
